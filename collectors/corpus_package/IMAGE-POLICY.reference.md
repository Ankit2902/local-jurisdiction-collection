# Image handling policy

The user reaffirmed the existing corpus convention on October 17, 2026: **do not collect image assets; replace all images with the exact literal `[IMAGE]`**. This instruction governs the final collectors and overrides the earlier implementation-stage requirement to download images.

The original [output contract](../../packages/local-extraction-handoff-2026-10-15/OUTPUT-CONTRACT.md#content-fidelity) already specifies ordered `[IMAGE]` placeholders. The current instruction makes the acquisition exclusion explicit.

- Do not request, download, extract, decode, render, OCR, or save separate image binaries as collection output. Ordinary browser image resources are blocked where the browser workflow supports that without changing access/challenge controls.
- Replace source images in normalized text and HTML with `[IMAGE]` in source order. Handle ordinary images, picture/source alternatives, inline SVG, image-only provisions and CSS image references. Preserve surrounding text, captions and labels already available as text.
- Retain each provision's source ID, heading, hierarchy and provenance. An image-only body becomes `[IMAGE]`; it must not be discarded or treated as an unexplained empty section.
- Keep image reference/omission metadata, including the source locator where available. Do not leave active image tags, image data URIs or CSS image fetches in normalized HTML. The same image-byte exclusion applies recursively to normalized JSON and metadata, including legal notes, captions and source attributes. If an attribute embeds image bytes, retain an omission marker and a hash of the original attribute instead of copying its payload.
- Intentionally omitted images are policy exclusions, not failed required attachments. Completeness checks must verify placeholder coverage instead of image-byte acquisition. This does not claim that image contents have been transcribed.
- Nonimage legal documents, PDF publications and required document attachments retain their separate collection and coverage rules. Original publisher HTML, PDFs or bulk archives may inherently contain embedded images; retaining an original source file is distinct from extracting or downloading separate image assets. Normalized output follows the placeholder rule.
- PDF page output inserts placeholders for detected image objects without saving their pixels; source-family runbooks state detection and ordering limits. Image-only/scanned pages must not be represented as successfully extracted legal text merely because a placeholder exists.
- For a source-proven image-only PDF page with no text glyphs, the text-glyph comparison may be explicitly marked not applicable under this policy. Preserve the page identity, detected image-object coverage and `[IMAGE]` markers. Do not fail completeness solely because those pixels were deliberately omitted, and do not describe the page as transcribed. Any unexplained missing glyphs, text, tables or ownership remain collection failures.
- Native Word imports inspect document XML and preserve image/drawing positions as `[IMAGE]`. They must not read or extract embedded image members or follow external image relationships. Video poster images likewise require an ordered placeholder while preserving any available caption or fallback text.

Regression tests must cover image-only source nodes, image placeholders in text and HTML, SVG/CSS/picture cases, preserved source identity, no image-acquisition calls and completeness unaffected by intentional image omission. Nonimage attachment failures must continue to be reported.

The same exclusion applies to independent validation tools. Offline browser audits must parse source markup inertly and replace image elements, inline image payloads and image styles before attaching content to a live document. Blocking external requests alone does not prevent inline SVG or data-URI images from rendering. Keep original source bytes intact for provenance, and record any historical audit limitation separately from current-policy validation.

Before pushing a collector revision, run its applicable image/transport regressions and audit the selected normalized records and retained files for separate image binaries. Record the exact tested source revision. A successful raw-file acquisition or a placeholder count alone is not a full-publication fidelity check.

The normalized-output audit covers `records.jsonl`, `sections.jsonl`, `pdf-pages.jsonl`, `pages.jsonl` and `references.jsonl`, including recursive metadata. It also checks supplemental `dependencies.json`, `relationships.json`, `document-audits.json` and `source-inventory.json` when present. PDF-page output must receive the same image-payload and active-markup checks as section output. An audit that finds no recognized normalized record output fails rather than reporting a successful empty check.

Image-payload redaction must cover multiline data URIs and image data embedded in otherwise textual attributes or PDF annotation metadata. Removing only the URI prefix or its first whitespace-delimited segment is insufficient: continuation payload bytes must also be omitted, while unrelated source text remains available.

Earlier sealed validation evidence is immutable. Some exploratory runs predate this clarification and contain acquired images; they do not define the behavior of the final collectors. Final validation reports distinguish those historical runs from the current image policy.

Normalized audit scope also includes official `attachment-pages.jsonl` and normalized `native-attachments/*.json`, in addition to the existing record/reference/page streams and supplemental metadata. This does not open original PDF/DOCX binary members. Raw-source table QA must sanitize in an inert template before attaching nodes; aborting network after raw attachment alone cannot establish that inline images were never rendered.

Image context takes precedence over a data URI MIME label: an `img`, picture source, image-typed object/link, poster, or CSS image locator remains an image when its URI says `application/octet-stream`. Hash its complete payload-bearing locator without decoding it. Preserve ordinary nonimage document references and available legal prose. Normalized image download anchors must be inert; retain original source URLs only as provenance/omission metadata. Regression tests must exercise real record construction and assert that image-decoder and image-acquisition functions were not called.

Image controls and resource declarations are included: image-type form inputs, standalone `srcset`, namespaced SVG image elements, image preloads and icon links must not survive as active normalized markup. The normalized-output audit checks declared image context even when the source URL has no image extension. A plain PDF link or an inert original image URL in omission metadata remains valid provenance.

Image MIME classification normalizes surrounding whitespace and case before applying these rules. Whitespace must not turn an image-typed object, embed or metadata payload into an allowed opaque document. Regression checks include ordinary PDF controls so legal document references remain usable.

HTTP success and error responses use the same image exclusion. Check normalized response MIME before reading the body, including image responses with HTTP 403, 404 or 429. Retain status, headers and any publisher access stop while recording that the image body was intentionally omitted. Error handling must not acquire image bytes.

PDF image-stream guards must recognize inline image dictionaries that use `W`/`H` or `Width`/`Height` without an explicit image subtype. Refuse image-stream decoding before the underlying decoder runs, while allowing source page-content and font/text streams needed for legal text. Test both image refusals and nonimage controls; a corrected guard requires evidence bound to that corrected executable source.
