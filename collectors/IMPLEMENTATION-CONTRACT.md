# Full-publication collector implementation contract

This stage upgrades the 100 expansion targets from bounded validation to runnable standalone full-publication collection. Prior packages and archives are immutable evidence. Do not edit them. The parent integrates Git and publication; agents must not commit/push or modify the database.

Each family owns its directory under collectors/ and a same-named evidence directory under outputs/full-publication-validation-2026-10-17. Copy reusable source helpers into the owned directory; do not import from absolute original package paths. Runtime environments and large live raw evidence stay outside Git. Keep compact representative fixtures and machine-readable test/validation receipts in the family directory. Retain source-backed failure evidence. Do not silently relabel sample results as full publication results.

Required capabilities (subject to the user’s overriding [image policy](IMAGE-POLICY.md): images are never separately acquired and become `[IMAGE]` placeholders):
- Dynamic complete publication inventory, explicit pinned publication identity/edition, full traversal by default rather than hardcoded sample IDs. Any --max-items/limit is explicit and forces incomplete status.
- Stable source IDs, container-owned content and descendants reconciled without duplicate bodies. Retained raw source/HTML, legal text, heading/path, tables/spans, links, notes, source hashes.
- Durable checkpoints/resume bound to source identity and inventory hashes; do not accept corrupt/mismatched caches. Atomic writes; no overwriting unrelated existing outputs.
- Shared family rate gates, serial/default conservative requests, challenge/429 stop and Retry-After. Municode direct HTTP is still stopped; use the already qualified ordinary headed-browser route and existing gate. No bypasses or resets of access stops. Native export requests follow visible controls and observed public workflows only.
- Scope-aware coverage report: inventory counts and unique IDs, acquired/parsed IDs, justified exclusions, failures, duplicates, missing/extra IDs, container ownership, image placeholders/omissions and nonimage asset references/acquisition/failures, start/end source consistency. Report publication text, attachment, edition and jurisdiction coverage separately. Missing nodes, parse errors, unknown exclusions, unresolved required nonimage assets, edition drift, limits and partial resume must prevent the corresponding complete claim and return a nonzero/incomplete outcome.
- A standalone read-only verifier recomputes reconciliation from retained evidence (not merely trusting a stored success boolean). Fault-injection tests must demonstrate missing/duplicated/corrupt/wrong-edition/interrupted data cannot pass. Tests of resumed versus uninterrupted output should be meaningful and deterministic.
- Runnable fresh collection, resume and verify commands, explicit environment/dependencies, output schema, operational limits and full-run instructions. Use Python/Node/normal Chrome where appropriate; no Codex runtime dependency.
- Exercise final code on fresh live source, and complete at least one genuine publication-level run per family where feasible. Clearly distinguish full live publication completion, full native-file download, full retained-evidence replay, synthetic fault tests and bounded transport smoke. A chapter subset is not a whole municipal publication unless explicitly a separately published unit. Do not run all 100 full corpora merely to fill a matrix: validate reusable implementations and disclose target-level validation scope.

Validation report in each family: validation-summary.json with implementation status, exact commands/runtime, tested publication identity/URL, counts, evidence paths and hashes, live scope/completeness claims and limitations. Include compact retained fixtures sufficient for network-free verification without old absolute paths. Report frozen status and exact replay command to parent. Parent maintains the root scope/runbook and Git push.
