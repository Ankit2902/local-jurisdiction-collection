# Collection and recovery runbook

Use `README.md` for installation, formats and coverage meanings; use `validation-summary.json` for exact tested scopes and source/config identities. Work from the repository root with the portable Python/Node paths installed for this machine.

1. Select the exact publication config. Whole-code, native volume, current portal, legacy chapter set, Charter and secondary zoning families are distinct. Confirm the source URL, city/county identity, inventory selector and any effective-date warning. A different publisher/layout needs qualification before dispatch.
2. Choose a new empty output outside Git. Run `collect.py --config ... --out ...` without `--max-items` for full selected-publication collection. Keep ordinary Chrome visible for browser configs. The default shared gate must be shared by all copies/processes; never delete its access-stop state to force traffic.
3. Read `coverage.json` even after exit0. `requested_level=file_pages` establishes selected native files and all physical PDF pages only. PDF legal text/sections/tables remain subject to manual review. Exit3 may be an expected bounded test or a real gap; use missing IDs, required assets, required components, failures and source consistency to distinguish them.
4. After an interruption, inspect the retained last error and raw receipt. Resume with the same command plus `--resume`, identical config and exact executed source revision. If code/config/source changes, use a new output. A failed cached response is not automatically re-requested.
5. On HTTP403/429 or challenge, stop. Review the retained gate state/Retry-After and source policy before any operator release. This tool contains no bypass or challenge solver. No manually imported browser cookies or profile is used.
6. On edition/source drift, keep the evidence and start a new pinned run. Do not merge two source editions into a success by editing checkpoint flags. On unknown incorporation or nonimage attachment type, leave it required/unresolved until independently qualified. External hosting/404 alone never justifies optional status.
7. Images must remain `[IMAGE]`. Do not add image downloads, screenshot extraction, PDF pixel rendering or OCR around that user rule. Native original PDF/HTML/ZIP retention is allowed. Preserve source IDs/reference metadata. An opaque attachment may be an image; the collector leaves it unresolved instead of guessing.
8. Run `python -B collectors/official/verify.py /evidence/run`. It is offline/read-only and returns3 for incomplete evidence. Run `verify_suite.py --evidence /evidence/official` for the declared final proof bundle: expected incomplete scopes are checked as incomplete, and the suite returns0 only if all expectations/fault tests hold.
9. Before handoff, retain raw receipts, exact executed sources, config/inventory/checkpoint, JSONL/CSV and coverage together. Copy compact fixtures and implementation with the large bundle for relocation, excluding runtimes/profiles/cache. Preserve failed/preliminary attempts separately; they are not selected complete proof.

No generic operator whole-publication import is implemented in this release. Burlington's supported route is ordinary-browser dynamic traversal of observed native HTML. If that route becomes blocked or its source structure changes, the result remains explicitly incomplete until a separately qualified full import/manifest workflow exists.
