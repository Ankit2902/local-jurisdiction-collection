# Isolated Gridics source-first and list candidate v2

This directory is a separate review candidate, not a production adapter or a new live proof. Production `collectors/gridics` and the frozen v1 candidate remain unchanged. Gridics has a persistent published workflow stop following the exact source-linked Cupertino PDF HEAD 403. The copied production access preflight runs before browser import/output creation; missing or altered advisory packaging cannot release the known stop. No new publisher request, CSS request, image download, or gate reset occurred in this work.

V2 includes the v1 source-tree-first acquisition changes. Each original native inventory root is retained before DOM waiting. Missing/untyped headings preserve IDs, bodies, ownership and order with explicit qualification errors. An exact renderer captured in the same phase/epoch is required to classify source-unrenderable roots; otherwise ordinary DOM timeout is a diagnostic gap. Full opening/closing native JSON trees are compared. The actual Miami Comprehensive Education root fixture has 104 nodes and 52 body owners: no unlabelled root is dropped, no heading is invented, and native-only/unknown-heading evidence cannot yield publication completeness.

The new list normalizer retains safe source classes and exact counter/style metadata in `record.lists`, bound by `source_list_sha256`. Plain text supports declared numeric/alpha/Roman markers and explicit square/circle/disc/none markers. It does not turn square or other nonnumeric styles into decimal numbers. Custom classes such as `paren-value-paren`, `value-paren`, `style-square`, and `default-style` remain in normalized HTML and source metadata; the collector does not guess punctuation from their names. Unsupported class, counter, per-item or malformed formatting is marked unqualified. `coverage.list_marker_qualification_gaps` identifies the owner/list/reasons, and affected records remain `source_unqualified`.

The required external stylesheet definitions were not retained by earlier captures. `../list-css-offline-inspection.json` binds the inspected original/full HTML and publisher JS. A small exact original HTML fixture here demonstrates the observed `/build/css/gridics.css?tmudor` locator, not its unavailable body or marker rules. No stylesheet was requested while stopped.

For a future legitimately authorized collection, the ordinary browser's **actually observed first-party stylesheet responses** are retained as original source only. Their receipt includes resource type, URL, owner document, phase, epoch, timestamp, MIME, byte count and SHA. The offline verifier checks the receipt and reports owner binding. CSS URLs are never discovered, fetched or imported by this collector, and CSS image assets are never imported. Retaining CSS by itself does not qualify custom punctuation: `marker_rules_interpreted` stays false. This capture path has fixture/fake-response tests, not a new live integration proof.

All image resources are blocked where practical. A known image MIME is rejected before response body reading; an image signature under a misleading MIME is not retained. Original legal HTML/JSON/PDF/CSS may contain embedded image references, but no separate image binary is saved. Normalized images and CSS image declarations become the literal `[IMAGE]`; omission/list metadata hashes embedded data-image payloads rather than copying them. The source labels, citations, captions, IDs, owned bodies and source order remain. No image decoding or extraction occurs.

`candidate-v2-final-tests.log` records 62 passing tests against exact final runtime bytes. These include the actual full Education root, actual Miami full-root list/table fixture, declared/custom marker cases, image payload and cell placeholders, image-MIME-before-body tripwires, mislabeled image signatures, observed stylesheet selection, phase/epoch/hash/owner binding, and access-stop/no-browser tripwires. `FINAL-SOURCE-MANIFEST.json` binds all candidate source, tests and compact fixtures. The earlier test log is retained as intermediate history.

The full retained Miami and Cupertino derivative is run by `replay_v2_sources.py` with socket connection tripwires. It checks all records, IDs, ownership, child order and source hashes against v1; legal HTML must remain identical after removing only the newly retained list attributes. It independently enumerates lists from original native BodyM HTML and verifies the normalized list inventory/classes/item counts/source hashes. It audits normalized records for active images and data-image payloads, verifies complete opening/closing native equality, and hashes all source inputs before/after. This is an offline derivative of previously acquired source, not a newly executed collection. Results are in `full-source-replay-summary.json` when terminal; the log/progress file show an incomplete run until then.

The source-inventory fields are deliberately narrower than legal completeness. `native_inventory_capture_complete` means all observed opening/closing native inventories/trees were retained and reconciled. `native_source_complete` in historical model output means stable captured native trees/records; it does not qualify missing headings, custom marker formatting, DOM witnesses, attachments or legal semantics. Separate text/asset/qualification flags remain false wherever gaps exist. No whole-jurisdiction completeness is claimed.
