# Legacy UPOC original-font metadata study — no additional mapping qualified

This isolated study examines only the exact original legacy 40th-edition/2024 UPOC PDF, SHA-256 `877c6e874d4de7873d22dd51443fd5c42169445ad2955db3836841a105a57102`. It preserves the prior finite source proof unchanged and searches actual embedded-font/XRef metadata for further defensible Unicode witnesses. **No new Unicode mappings were found under those source guards.** No production source, original PDF, legal text, Git, database, publisher state or prior sealed proof changed.

The remaining inventory is `UNRESOLVED-INVENTORY.json`, with a concise `unresolved-cids.csv`. It contains 71 distinct original font/CID pairs and all 4,447 unresolved source positions carried from the hash-bound original text-operator ledger: font object 620 / Arial-BoldMT has 54 unresolved CIDs and 4,346 occurrences; object 628 / Arial-ItalicMT has 17 CIDs and 101 occurrences. Each entry retains physical pages, text operator/string index, byte offset, original operand hash, original GID/Identity mapping, raw font-table glyph hash/length, advance/LSB metrics, actual cmap-witness availability and the explicit reason Unicode remains null. No character is supplied from its CID integer, alphabetic order, typography, legal context or a synthetic glyph name.

`prior-proof/` is an exact copy of the independently reviewed 15-file prior packet, manifest `2d29388868e879debedbb3a8f56731f4849dea1ca42d3fd77dd74ec96857f53e`. Its original 30 mappings (17 bold, 13 italic) reproduce exactly using explicit original same-face/version cmap witnesses plus identical GID raw glyf bytes and advance/LSB metrics. Their 3,382 previously source-supported occurrences remain supported; no old mapping is weakened or silently expanded. The copied full 814-run / 7,829-unit ledger is retained evidence, not a newly claimed 102-page content replay. Historical comments in that packet about table gaps describe its earlier state and do not override later independent canonical table repairs.

The new metadata census examines 1,001 original XRef object dictionaries, 16 font objects and ten page-resource font objects, without decoding page images or parsing every body page. The two target fonts have no ToUnicode, cmap or post table. The only embedded same-face/version semantic witnesses, objects 623 and 626, have 18 and 13 explicit Unicode cmap entries respectively. Their original Macintosh/MacRoman cmap entries add no further supported meaning. Both witnesses have post format 3, which contains no glyph names. FontTools names such as `glyph00057` are generated display labels and are explicitly not source Unicode authority.

Other original ToUnicode fonts are different declared font faces and cannot supply these targets' meaning. Original object 909 names Arial-BoldMT and declares WinAnsiEncoding, but has no embedded font program/GID witness. Width alone is not a unique semantic mapping. Unreferenced Helvetica and ZapfDingbats objects were also inventoried, rather than overlooked; they provide no same-face embedded witness. No installed font, newer UPOC edition, font download, rendering, glyph-image/contour recognition or OCR is used. Reading/hashing raw embedded font tables for exact binary identity does not interpret glyph appearance.

The finite actual body scope is physical pages 9, 38, 107, 169 and 170. Their 96 original target-font text runs exactly reproduce the prior ledger's operator positions, raw operand hashes and CID units. These pages directly cover 59 of the 71 unresolved pairs; the other twelve are inventory entries from the retained source-bound ledger, not fresh body parses. Five-page PDFMiner glyph metadata and independent PDFium raw character indices/bounds produce 853 exact CID-passthrough geometry matches. Those raw codepoints often happen to resemble unrelated letters or symbols; they are **not Unicode witnesses**. Two known CID-3 spaces have no selected native geometry match and remain explicit. Their previously supported U+0020 meaning still comes from the original font-table identity proof, not the native reader. No partial diagnostic string is promoted into operative legal text.

The selected five pages contain zero image objects. Literal `[IMAGE]` remains the image policy; no image position or ownership is changed. Study and read-only replay block network, PDF image stream decoding, image extraction, bitmap access, object rendering and OCR-related rendering APIs. Native PDFs are retained unchanged as original documents; there are no separate acquired or extracted images.

`STUDY.json` contains the complete new metadata census, mapping search, unresolved source inventory and finite probes. `SUMMARY.json` summarizes the outcome. `source/legacy-upoc.pdf` and its original HTTP receipt bind the input. `SOURCE-LINEAGE.json` records the exact copied prior proof. The source edition remains the older linked publication; this study does not resolve the primary source's 42nd-edition/adoption conflict or qualify all 102 affected pages, whole-book text, tables or publication completeness.

Tested on Python 3.12.14 / macOS 26.6.2 arm64 with the exact existing family requirements, including FontTools 4.67.0. There are no added dependencies. From this directory, use an environment with `requirements.txt` installed:

```sh

python -B -m unittest test_study -v
```

The verifier uses only relative retained inputs. It rereads the original metadata and five body pages, compares the complete study and JSON/CSV inventory, checks evidence bytes remain unchanged, and writes only to stdout. It does not restore missing files or contact a publisher. Generation uses `study.py` and refuses to overwrite `STUDY.json`; `write_inventory.py` deterministically projects the source inventory and also refuses to overwrite retained outputs.
