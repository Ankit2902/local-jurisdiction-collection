Every native probe first pins the corrected retained_native.py guard SHA256 f7ef2d7ec3e12454c13be9fcb099c93f806b0a3ed451501bfc84f8707bb04bf3 and PDF source hash, then runs inside that guard. Cached 172-page records show 102 pages with both undecoded CID literals and independent-engine failures. Their text contains 7,829 literal `(cid:N)` tokens covering 72 distinct numeric values. These numeric values are not a complete mapping: CID identity is font-specific. The prior 28,603 source words, 46 exact [IMAGE] positions and 745 detected cells remain as recorded, with all 102 failures unresolved.

The source font-resource census inspects resource dictionaries across all 172 pages, not a full native page/word/table replay. It finds ten font objects and nine embedded font programs. Font 620:0 is Type0 `/KCOEDF+Arial-BoldMT`, Identity-H and CIDToGIDMap Identity, but lacks ToUnicode; its embedded TrueType subset has no cmap/post character names. It appears in the font resources of exactly the 102 failing pages. Font 628:0 is similarly unmapped `/KCOEGJ+Arial-ItalicMT`, present on four pages. PDFium's values reflect the raw CIDs rather than a trustworthy Unicode spelling in these contexts; no engine's output is substituted for another.

Three bounded text-operator probes on physical pages 7, 9 and 12 inspect 4,080 source text glyph operations, including font object, CID, source text matrix and advance. There are no marked-content text witnesses on these pages. A structure-only traversal exhausts 123 StructTreeRoot dictionary nodes and finds no ActualText anywhere in that tree; MarkInfo is false. No page image or Alt payload is read for this traversal.

The same PDF also embeds separate Unicode-cmap TrueType subsets for Arial bold (623:0; 18 cmap entries) and italic (626:0; 13 entries). `compare_raw_font_programs.py` proves only finite partial candidates by exact, unique, nonempty/non-composite raw glyph-program byte identity, matching source hmtx metrics, identical fpgm/prep/cvt tables and unitsPerEm, and the explicit Unicode cmap in the counterpart source font. It reads raw sfnt table byte slices using loca offsets. It does not decode glyph points/outlines or recognize shapes. This supplies 16 bold and 12 italic mappings. Empty/unmatched glyphs, including space, are not extrapolated.

For the bounded pages, bold font 620:0 uses 47 CIDs, with 32 unresolved after those witnesses. Italic font 628:0 uses 19 CIDs, with seven unresolved. The partial map therefore cannot resolve even the bounded sample, and cannot qualify 102 pages. No new normalized output or qualification is produced. No character is inferred from expected prose, CID arithmetic, a different font style's numbering, glyph shape recognition or OCR.

Early diagnostics in probe_fonts.py/inventory_fonts.py used fontTools metadata and reserialized glyph-program hashes. Those compiled hashes are retained as diagnostic history only and are not the qualification witness. The final finite candidate uses independently read exact raw glyph byte slices; it imports no fontTools and performs no outline/point decoding. No glyph shapes or images were rendered or interpreted in either phase.

Costs are bounded: first four-page font metadata probe 0.13 s; all-page resource/font dictionary inventory 0.20 s; three-page text/CID operator probe 0.29 s; exact raw font-program comparison 0.20 s.
