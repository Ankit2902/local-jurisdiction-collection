# Selected-publication and jurisdiction-readiness audit

This is a read-only audit of the current source and exact current/historical Flagstaff inputs. It is not a legal opinion or an assessment that every law applicable within Flagstaff has been collected. No collector, launcher, registry, original source, earlier evidence packet, or production corpus-writer file was modified.

The existing selected-publication acceptance is correct for the current Flagstaff primary. Its separate common read-only receipt is `verified_publication`, exit 0, with no acceptance gaps. The full selected City Code, including its published Charter component, has 361 acquired documents, 2,661 owned records, 377 tables, 24,237 blocks and 882 literal `[IMAGE]` markers. Source consistency and the finite source-target ledger pass. Three literal browser fragments remain malformed; the qualified same-publication target resolutions are preserved separately. Native capture is false, edition completeness is null and jurisdiction completeness is false. The proposed dimension does not change any of these facts.

## What the contracts actually require

The original [OUTPUT-CONTRACT](../../../../../../../github/local-jurisdiction-collection/packages/local-extraction-handoff-2026-10-15/OUTPUT-CONTRACT.md) describes **jurisdiction** readiness at lines 93–104. It requires an evidenced disposition for every discovered family and every in-scope node (95), no unresolved substantive text/version/identity (96), independent reconciliation (97), source-sensitive comparisons (99), file/hash equality (100), meaningful replay/resume equivalence (101), and a report distinguishing automated from human comparisons (102). It does not name three mandatory Boolean flags or say that a corpus serializer must perform or infer an independent final legal review. Lines 30 and 72–83 permit explicit scope dispositions rather than silently treating every separate publication or reference as part of a single codified book. Lines 36–46 define the 16-field compatibility representation independently of those completion claims.

The [implementation contract](../../../../../../../github/local-jurisdiction-collection/collectors/IMPLEMENTATION-CONTRACT.md), lines 8–15, requires complete traversal of the **selected publication**, source ownership and structure, and separate text/attachment/edition/jurisdiction dimensions. Unknown or missing required nonimage documents must block the corresponding claim. A successful selected publication does not establish every jurisdictional family or every incorporated legal layer.

## Why strict readiness remains false

The exact current production code is `collectors/corpus_package/common.py:146–148`. `downstream_ready`, `complete` and status require all five inherited values to be literal true: `publication_accepted`, `complete`, `whole_jurisdiction_complete`, `external_adopted_legal_dependency_closure_complete`, and `independent_final_review_complete`, plus no unresolved source dispositions.

For originals these last three are **unconditional false defaults**, not computed findings that three additional publisher downloads failed. See `collectors/originals/workflow.py:18–25` and the explicit `false_defaults` declaration in `collectors/originals/integration-contract.json:21–24`. `workflow.py:25` also contains a fixed independent-review note; it is not a reader of later independent audit receipts. `collectors/originals/README.md:75–86` already distinguishes implemented primary gates from broader scope and independent final review.

Thus a current source/structure/export proof can be good while the strict report remains incomplete. The hardcoded defaults are conservative and should not be silently flipped. The defect is the absence of a clearly named selected-publication export readiness dimension, which makes a sound current selected publication operationally indistinguishable from a historical primary with a genuine source-consistency failure. The proposed isolated addition addresses only that distinction. Strict fields and CLI exit semantics remain byte-for-byte equivalent apart from the new named report fields and run-manifest field.

The standard launcher’s selected-publication logic does not impose a blanket external-model-code-library requirement. `collectors/ops/launcher.py:499–503` requires original text, attachments, qualified structure and source consistency. Lines 520–542 reconcile explicitly configured separate-publication dependencies and expose publication acceptance separately from jurisdiction. The current common receipt passes those gates. No global legal-scope waiver is needed to recognize that existing result.

The finite independently governed state/federal references are classified under exact source/context rules in `flagstaff_html_normalize.py:14–15,128–148` and `source_navigation.py:46–57`; this is not a general exemption for incorporated books.

## Minimal isolated addition

`Projection.readiness_evidence` is an optional, default-null reader field. Only the independently identified `original-flagstaff-az-primary` reader currently supplies schema `flagstaff-selected-publication-readiness-evidence-1` and contract `flagstaff-bound-common-publication-acceptance-1`. Existing Municode/enCodePlus readers remain fail-closed (`reader_has_no_qualified_readiness_evidence`); family success strings or serialization alone cannot qualify them.

The new `selected_publication_ready` requires exact source/config/version/coverage bindings, unchanged source/runtime proof maps, actual standard common exit-0 acceptance, family raw replay/route/chronology proof, publication bodies/text, nonimage dependencies, source consistency and legal structure, no standard acceptance/dependency gaps, and no unresolved exported source dispositions. Missing, false or non-Boolean gate values fail. A 64-character digest is provenance binding, not authentication of an adversarially fabricated receipt; the reader continues to validate actual immutable input hashes, raw receipts and source evidence.

It does **not** infer independent legal review, edition/date interpretation, all jurisdictional families, external legal layers, native PDF structure, or a different selected publication. Existing inherited coverage is unchanged, as are strict status, `complete`, `downstream_ready`, and CLI exit codes. Named reader contracts can later be added for other families only after independent source/structure/dependency proof qualification, particularly their real required nonimage PDFs.
